# BEMO — تدقيق التوافق وخطة التحسين التدريجي

تاريخ المراجعة: ١ نوفمبر ٢٠٢٦. المرجع: Master Blueprint V4.2، والملاحق 01 و02 و03، وتوجيه التحسين التدريجي الأخير.

## النتيجة الرئيسية

المشروع الحالي واجهة ثابتة مكتوبة بـ HTML وCSS وJavaScript، وليست تطبيق React أو مشروع Supabase متصلاً. توجد واجهة تسوق قابلة للاستخدام التجريبي: منتجات ومفضلة وبحث وسلة متعددة المتاجر ومحاكاة طلبات. سنحافظ عليها، ونضيف نموذجي الرئيسية والبحث في مسار منفصل للمراجعة. لا تُعد البيانات الاصطناعية أو نماذج الواجهة تنفيذًا تشغيليًا لنظام التحقق أو البحث في قاعدة البيانات.

خط الأساس المنشور هو المراجعة `9f0c3e22390b989d97a65213a2d49bccba7ebae7`. توجد نقطة الرجوع `bemo-before-enhancements-20261101`. معرّف الموقع باقٍ `appgprj_6ae631a402088191af937682c72afc07`، وملف الاستضافة يوجّه إلى `dist`. لا يوجد ما يبرر استبدال المشروع أو تغيير محرك الواجهات لتنفيذ النماذج المطلوبة.

## ١. ما تم فحصه فعليًا

| الجزء | الدليل الموجود | الحالة الدقيقة |
|---|---|---|
| الصفحة الأساسية | `dist/index.html` | هيكل متجر واحد الصفحة، أقسام ومربعات حوار |
| المظهر والاستجابة | `dist/styles.css` | ألوان أخضر/كريمي، شبكة 4 أعمدة ثم عمودين، قواعد RTL ونقاط استجابة |
| السلوك | `dist/app.js` | أحداث واجهة، تصفية وفرز، مفضلة وسلة وطلبات في `localStorage` |
| المحتوى | `dist/catalog.js` | 12 منتجًا افتراضيًا و3 متاجر افتراضية، نصوص عربية/إنجليزية وصور توضيحية |
| الاستضافة | `.openai/hosting.json` | موقع ثابت على Sites؛ لم يُضف خادم تطبيق |
| تسجيل الدخول | نافذة تعريفية داخل `app.js` | Google/Supabase غير متصل؛ تسجيل ChatGPT عند بوابة الاستضافة ليس حساب بائع في BEMO |
| قاعدة البيانات وواجهات API | لا مخطط أو اتصال تشغيلي في خط الأساس | غير موجودة؛ وأكد المالك أنه لا يملك مشروع Supabase بعد |
| الحزم | لا `package.json` أو lockfile أو إطار مكونات في خط الأساس | لا حزم JavaScript مثبتة داخل المشروع |
| الشارات والإدارة | لا جداول أو قرارات أو أدلة تحقق في خط الأساس | غير موجودة تشغيليًا |

الملفات الجديدة تحت `dist/design-preview/` و`tests/` و`docs/` إضافات منفصلة قيد المراجعة. لا تغيّر وحدها حالة خط الأساس إلى «نظام إنتاجي». أي مخطط SQL أو واجهة إدارة قيد الكتابة لا يدخل ضمن الميزات المكتملة إلا بعد مراجعته وتنفيذه واختباره في بيئة مصرح بها.

## ٦. خطة الملفات والدمج الآمن

1. **A — تدقيق وتثبيت خط الأساس:** هذا التقرير و`docs/PROTOTYPE_PLAN_AR.md` ونقطة الرجوع المذكورة. الحفاظ على الملفات الأربعة الأصلية وإعداد الاستضافة. لا ترحيل بيانات أو تغيير مفاتيح.
2. **B — خطة مكوّنات:** إعادة استخدام الكتالوج والترجمة ومفاهيم البطاقات والنوافذ. تعريف رموز الألوان والمسافات الجديدة في ملفات النموذج. لا ربط CSS الجديد بالمتجر الحالي.
3. **C — نموذج الرئيسية:** ملفات إضافية `dist/design-preview/index.html` و`design.css` و`homepage.js`. يعيد استخدام `../catalog.js`؛ لا تعديل قواعد السلة أو الطلب.
4. **C — نموذج البحث:** ملفات `dist/design-preview/search.html` و`search.css` و`search.js` و`search-fixtures.js`. مقدم `BemoSearchProvider` وبيانات مناطق وشارات ومخزون اصطناعية مُعلنة؛ لا تسجيل أدلة تحقق أو منح حقيقي.
5. **بوابة اعتماد:** عرض الرئيسية والبحث بالعربية والإنجليزية وعلى الهاتف والكمبيوتر. يحتاج التعميم على الصفحة الأساسية إلى موافقة المالك الصريحة.
6. **D — دمج الواجهة بعد الاعتماد:** تعديل محدود ومتدرج لـ`dist/index.html` و`styles.css` و`app.js`، بدءًا بالرموز والرأس والبطاقات، ثم الصفحة الرئيسية والبحث. اختبار رجوع لكل خطوة قبل نشرها.
7. **E — البيانات والتحقق والبحث بعد اعتماد البنية:** إضافة ترحيلات غير هادمة فقط. الكيانات المقترحة: تصنيفات/علامات/مناطق شحن، وتعريفات وقواعد ومنح وطلبات وأدلة واستئنافات الشارات. نمط Google/Supabase باقٍ. عقد بحث بصفحات محدودة وحقول عامة؛ قاعدة البيانات مصدر الحقيقة. أسماء ملفات الترحيلات النهائية تُثبّت عند اعتماد المخطط، لا تُقدّم الآن كملفات منفذة.
8. **F — التحقق التشغيلي:** حسابات متعددة، عزل المتاجر، تحقق البيانات الخاصة، رفض منح البائع لنفسه، تزامن المخزون، اختلاف الشحن، إبطال شارة مسحوبة، وعدم أثر البحث على الطلبات. لا تفعيل عام قبل اجتياز الاختبارات وسياسات التشغيل.

عند الربط لاحقًا، يجب فصل مفاتيح التخزين التجريبي عن الحقيقي. `app.js` الحالي يحوّل معرفات المنتجات إلى أرقام باستخدام `+` ويجمع السلة حسب اسم المتجر؛ ربط UUID ومعرّفات متاجر ثابتة يحتاج محوّل بيانات واضح واختبارات، وليس استبدال بيانات العينة مباشرة.

## ٧. سجل التحقق وحدوده

فُحصت ملفات خط الأساس والبيان وتاريخ Git، وتأكد وجود نقطة الرجوع. أُجريت قراءة مباشرة لقواعد CSS والوظائف؛ القياسات المذكورة لأهداف اللمس مستخرجة من CSS وليست تقرير قارئ شاشة.

شُغّل `node tests/search-prototype.cjs` ونجحت **11 حالة** على بيانات النموذج: اكتمال الوجهة للشحن المجاني؛ اختلافه بين وجهتين؛ استبعاد الوجهة غير المدعومة؛ OR للشارات؛ استبعاد المسحوب والمنتهي؛ البحث بالاسم العام للمتجر؛ تراكم التصنيف/السعر/المخزون؛ استبعاد عملة مختلفة؛ تطبيع حركات عربية؛ صفحات محدودة؛ وترتيب السعر. هذه اختبارات دوال محلية، وليست اختبار قاعدة بيانات أو صلاحيات أو OAuth أو أداء إنتاجي.

تبقى اختبارات المتصفح للنموذج ومراجعة صور 360/768/1280/1440، و200% zoom، ولوحة المفاتيح، والتباين، وURL/back والحالات الفارغة موثّقة في تقرير التنفيذ النهائي بعد إجرائها. لا تُعد قائمة الاختبارات المخطط لها نتائج نجاح.
