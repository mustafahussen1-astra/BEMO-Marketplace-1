# تنفيذ أدوات التاجر

الحالة: خلفية المنتجات والصور مطبّقة على BEMO Development بتاريخ ٦ نوفمبر ٢٠٢٦؛ واجهة البائع قيد النشر والفحص الفعلي.

اعتمد المالك إكمال النظام في ٦ نوفمبر ٢٠٢٦. يحتفظ التنفيذ بمشروع Supabase وموقع Sites والتصميم الحاليين. لا يتطلب إضافة خدمة مدفوعة أو تغيير إطار العمل.

- يبدأ الكتالوج الحقيقي فارغاً. يضيف التاجر المنتجات والصور والمتغيرات والأسعار والكميات بنفسه.
- إعداد التوصيل مبلغ يحدده التاجر لكل طلب من متجره، مع العملة. لا تُضاف مناطق توصيل في النطاق الحالي وفق توضيح المالك الأحدث.
- المبالغ وحدات نقدية صحيحة، دون جمع عملات مختلفة أو تحويل تلقائي. تُحفظ الأسعار والتوصيل لاحقاً ضمن نسخة الطلب عند إنشائه.
- المنتج ملك متجر واحد؛ رمز SKU فريد داخل المتجر. حالات المسودة والنشر والإخفاء والأرشفة مستقلة عن التعليق الإداري.
- تعديل الكميات يسجل حركة مخزون بسبب ومفتاح منع التكرار. قبول الطلب لاحقاً يخصم مخزونه مرة واحدة داخل معاملة واحدة؛ إنشاء الطلب لا يحجز المخزون.
- يعاد استخدام التحقق من جلسة Google وصلاحيات المالك الموجود. الجداول داخل المخطط الخاص، والوصول عبر عمليات محددة، دون كشف بريد المالك في الكتالوج.
- الصور: رفع مأذون إلى مخزن المشروع الحالي، مع حدود نوع وحجم وعدد، وعرض صور المنتجات المنشورة فقط للزوار.
- اختبار حسابين محلياً ضد قاعدة PostgreSQL، ثم فحوص الخدمة والواجهة. لا تُزرع منتجات أو طلبات وهمية في بيانات المالك الحقيقية.

ترتيب الإكمال: عقود المنتجات والمخزون والتوصيل؛ الصور؛ واجهة البائع والكتالوج؛ الطلبات؛ الدعم والإرجاع؛ الإدارة والشارات والإشعارات؛ اختبارات الإطلاق والاسترداد. كل حالة إنجاز تُسجل مع أدلتها في نقطة الاستئناف.
