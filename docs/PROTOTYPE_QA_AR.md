# BEMO — تسليم نموذج المراجعة ونتائج الفحص

التاريخ: ٢ نوفمبر ٢٠٢٦. المرحلة المكتملة: التدقيق والخطة ونماذج المراجعة (A–C). هذا ليس إطلاقاً تشغيلياً للسوق.

## ما أُنجز

- نموذج رئيسية برتقالي: حملات توضيحية، تصنيفات، عروض العينة، بطاقات متاجر، اكتشاف منتجات وفرز، مفضلة داخل النموذج، ونافذة تفاصيل.
- نموذج بحث: منتجات ومتاجر وأسماء فرق بائعين عامة، تصنيف وعلامة وسعر ومخزون تجريبي، وجهات مترابطة، شارات متعددة، فرز وترقيم واقتراحات بحث، وفلاتر هاتف مع تطبيق وإعادة ضبط.
- العربية RTL والإنجليزية LTR، وحفظ حالة البحث في الرابط وإعادتها بالرجوع.
- إبراز أن الشارات والمخزون والتقييمات والوجهات اصطناعية. لا طلبات حقيقية ولا منح شارات من هذه الصفحات.

## ما أُعيد استخدامه وما أُضيف

أُعيد استخدام `catalog.js` وصوره وأسماء المنتجات والمتاجر، وعناصر المتصفح الأصلية مثل form/select/dialog. لم تُضف حزم أو خدمات مدفوعة أو إطار واجهات. الخطان Inter وNoto Sans Arabic من Google Fonts؛ تفاصيل المصادر والتراخيص وحدود الصور في تقرير التدقيق.

كُتب CSS وJavaScript خاصان بالنموذج وعقد مقدم بحث قابل للاستبدال، لأن المشروع الحالي ثابت ولا يستخدم React أو نظام مكوّنات يمكن إدخاله دون تغيير بنيوي غير ضروري. بيانات الاختبار محصورة في `search-fixtures.js`.

## الملفات

الملفات التنفيذية الجديدة السبعة داخل `dist/design-preview/`: `index.html`، `design.css`، `homepage.js`، `search.html`، `search.css`، `search.js`، `search-fixtures.js`.

أُضيف `tests/search-prototype.cjs` وأربعة تقارير داخل `docs/`. لم تتغير ملفات المتجر الأصلية `dist/index.html` و`dist/styles.css` و`dist/app.js` و`dist/catalog.js`، ولا بيان الاستضافة. أثبتت مقارنة Git ذلك مع المراجعة `9f0c3e22390b989d97a65213a2d49bccba7ebae7`. نقطة الرجوع: `bemo-before-enhancements-20261101`.

## نتائج الاختبار الفعلية

1. نجحت 11 حالة في اختبار مقدم البحث المحلي: اكتمال الوجهة للشحن المجاني، اختلاف الرسوم بين وجهتين، استبعاد الوجهة غير المدعومة، OR للشارات، استبعاد المسحوب والمنتهي، مطابقة المتجر، اجتماع التصنيف والسعر والمخزون، اختلاف العملة، تطبيع العربية، حدود الصفحات، وفرز السعر.
2. نجحت فحوص صياغة ملفات JavaScript الثلاثة.
3. في المتصفح: الدولة ألف/الشمال/الحديقة مع الشحن المجاني أعادت 3 منتجات ومتجراً واحداً؛ الدولة باء/الساحل/الخليج عبر نافذة الهاتف أعادت 4 منتجات. هذه نتائج بيانات اختبار فقط.
4. ثبت بقاء تركيز لوحة المفاتيح بعد تغيير فلاتر سطح المكتب. زر Escape أغلق نافذة الهاتف وأعاد التركيز لزر الفلاتر. عاد زر الرجوع من الوجهة المطبقة إلى النتائج السابقة.
5. عمل اقتراح «سماعات» بالأسهم وEnter وأعاد منتجاً واحداً؛ فتحت تفاصيله وأُغلقت بـEscape. أظهر استعلام بلا تطابق الحالة الفارغة.
6. عمل تبديل اللغة في الرئيسية على الهاتف وفي البحث على الكمبيوتر. رابط عروض الرئيسية مرّر `offer=1` وأعاد عروض العينة الخمسة.
7. فُحصت الرئيسية والبحث عند قياسات نافذة 360 و768 و1280 و1440 بكسل. لم يظهر تجاوز أفقي لجسم الصفحة في القياسات المفحوصة؛ شرائط التصنيفات لها تمرير داخلي مقصود. حُفظت صور لكل قياس في مجلد التسليم.
8. عُرضت المنتجات بعمودين على الهاتف، وثلاثة على الجهاز اللوحي، وأربعة بوسط الكمبيوتر، وخمسة بالعرض الواسع. أُصلح اختفاء زر اللغة بالجوال وأهداف لمس رقائق الفلاتر الأقل من 44px.
9. لم تظهر أخطاء JavaScript في سجل المتصفح أثناء فحص البحث الأخير.

أُصلحت أثناء الاختبار مشكلة بقاء خيار الشحن المجاني معطلاً بعد اختيار مدينة في نافذة الهاتف؛ أعيد الاختبار ونجح.

## حدود الفحص وما بقي

- لم تُختبر قاعدة بيانات أو سياسات صلاحيات أو Google OAuth أو قبول طلب حقيقي: هذه الخدمات غير مربوطة ولا يوجد مشروع Supabase لدى المالك.
- لم يُجر اختبار قارئ شاشة كامل أو تكبير 200% أو قياس Core Web Vitals أو تدقيق تباين شامل أو اختبار ضغط. الاختبارات أعلاه لا تعني اعتماد WCAG كاملاً.
- الصور خارجية وتوضيحية، والتحميل يعتمد الشبكة. لا دليل أداء إنتاجي ولا بيانات تجارية فعلية.
- لم يُعد تشغيل كل سيناريو شراء للمتجر الأصلي في هذه الجولة؛ ملفات تنفيذه لم تتغير. يلزم اختبار رجوع كامل عند الدمج بعد الاعتماد.
- روابط الحساب والسلة والطلبات في النموذج تفتح المتجر الحالي، ولا تفتح عمليات حقيقية من النموذج. وُضّح مقصدها في وصف الوصول وعنوان الرابط.
- البحث هنا محلي. البحث الحقيقي يحتاج مخططاً ومقدم بيانات وصلاحيات وقواعد شحن ومخزون ومصادر تقييم موثوقة؛ شارات الأزرق والذهبي تحتاج أدلة فعلية والأخضر قواعد معتمدة.

## القرار التالي

اعتماد بصري للرئيسية والبحث قبل تطبيقهما على المتجر، حسب توجيه المالك: “Present these for my visual approval before applying the complete storefront redesign.”

اعتماد التصميم وحده لا يعني اعتماد تغيير البنية أو تشغيل الشارات. خطة الخلفية منفصلة، وتتطلب إعداد Supabase وربط Google واعتماد السياسات ثم الاختبارات التشغيلية. لا تغيير في COD أو الرسوم أو قواعد إنشاء المتجر أو الوحدات المخفية.
